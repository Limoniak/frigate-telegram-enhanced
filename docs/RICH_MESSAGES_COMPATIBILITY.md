# Telegram Rich Messages: compatibility

**Review date:** 2026-10-27

## Telegram Bot API

The implementation uses:

- `sendRichMessage` for text, menu, and rich media messages;
- `editMessageText` with `rich_message` for text and in-place media replacement;
- Rich photo, video, animation, and buttons blocks;
- callback data and URL buttons using the established action values.

As documented by Telegram, the required API feature levels are Bot API 10.1 for Rich Messages, 10.2 for media blocks, and 10.3 for rich button blocks. The current official Bot API changelog includes 10.3. Deployments pointed at an older self-hosted Bot API server may reject these methods or fields. There is no automatic legacy fallback or version negotiation; upgrade that server before enabling this release.

The code retains compatibility-facing Go methods such as `SendMessage`, `SendPhoto`, and `SendVideo`, but those wrappers now serialize through the Rich API. That preserves internal call sites and options; it does not preserve wire compatibility with old Bot API servers.

## Configuration and deployment

- No public configuration key or on-disk configuration migration is introduced by the Rich API transport.
- Existing chat IDs, recipient selection, camera filters, callback action values, quiet-hours behavior, and Frigate/MQTT setup remain the same.
- Existing media-in-place behavior is retained: the event message can be edited in place, or the follow-up can be sent as a reply according to the existing setting.
- Docker packaging/build configuration is unchanged. This review did not build or run a container.
- The new Rich API requirement is on the Telegram endpoint, not Frigate or MQTT. Frigate remains the source of snapshots, clips, and GIFs.

## Client support and limitations

- Rich rendering and button appearance are controlled by each Telegram client. The API supports left/center/right button-row alignment; it does not expose fixed button widths.
- The app requests left alignment and retains the logical rows already created by its inline keyboard markup.
- The HTML converter covers the markup currently generated by the app, not arbitrary HTML.
- Ambiguous edits avoid a duplicate fallback message. This can leave the tracked media `file_id` unknown until a fresh message is sent; using a stale ID could revert the message media.
- This branch has not been verified against an actual Telegram cloud endpoint or a self-hosted Bot API 10.3 server.
